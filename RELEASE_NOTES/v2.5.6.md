# v2.5.6 Technical Documentation: AMD/ROCm Compatibility

> Baseline commit: `836b488` (v2.5.5)
> Commits: `80582bb` (feature) / `6f1c2ff` (display-name gate fix) / `a484710` + `21f49a8` (README) / `ed78766` (changelog)

---

## ① Purpose

Add **AMD/ROCm compatibility** to the custom node. nunchaku requires NVIDIA CUDA and
cannot be imported on AMD/ROCm systems, which previously left every nunchaku-dependent
node registered but broken at runtime (obscure `ImportError`s when a workflow executed
them). This release makes the package detect a missing nunchaku at startup and adapt:

- **Disable** all nunchaku-dependent nodes on AMD/ROCm (they are not registered, so they
  do not appear in the node list at all).
- **Keep** the nunchaku-independent Krea2 ControlNet nodes fully functional on every
  platform (`Krea2ControlNetLoraLoader` and the Krea2 route of
  `NunchakuQI&ZITDiffsynthControlnet`).
- **Guard** every runtime nunchaku import so legacy workflows get a clear
  `RuntimeError` ("nunchaku is required...") instead of an obscure `ImportError`.

The implementation mirrors the approach already proven in the companion repository
`ComfyUI-NunchakuFluxLoraStacker` (PR #6 by 0xDELUXA + follow-up fixes), adapted to
this package's module layout.

### Requirements

1. **No regression on NVIDIA**: with nunchaku present, all 9 nodes must still register
   and behave exactly as before.
2. **Exclusive on AMD**: nunchaku-dependent nodes disabled, nunchaku-independent
   (Krea2) nodes available.
3. **Clean errors**: runtime nunchaku imports raise a descriptive `RuntimeError`, never
   a bare `ImportError`.
4. **Loader untouched**: `Krea2ControlNetLoraLoader` and the ControlNet node are not
   modified by this change.

```python
        from .nodes.lora.zimageturbo_v4 import GENERATED_NODES as ZIMAGETURBO_V4_NODES, GENERATED_DISPLAY_NAMES as ZIMAGETURBO_V4_NAMES

        for node_class in QWEN_V3_NODES.values():
            node_class.__version__ = __version__
        for node_class in QWEN_V1_NODES.values():
            node_class.__version__ = __version__
        for node_class in ZIMAGETURBO_V1_NODES.values():
```

### 3.2 `nunchaku_code/lora_qwen.py` — top-level import guard

```python
# It's assumed these functions from your project are available for import.
# If not, you'll need to provide their definitions.
try:
    from nunchaku.lora.flux.nunchaku_converter import (
        pack_lowrank_weight,
        reorder_adanorm_lora_up,
        unpack_lowrank_weight,
    )
    _NUNCHAKU_AVAILABLE = True

    # AMD/ROCm or missing nunchaku install: keep the module importable.
    # Any call into these helpers raises a clear error.

        raise RuntimeError(
            "nunchaku is required for QwenImage/Z-ImageTurbo LoRA composition, "

    reorder_adanorm_lora_up = _nunchaku_required
```

## ④ Detailed Code Explanation

### 4.0 Overall Architecture

```
ComfyUI startup
      │
      ▼
__init__.py: _NUNCHAKU_AVAILABLE probe
      │  try: import nunchaku  → True (NVIDIA)
      │  except ImportError    → False (AMD/ROCm)
      ▼
if _NUNCHAKU_AVAILABLE:
    register QwenImage / Z-ImageTurbo nodes (7)      ← NVIDIA only
else:
    skip them (warn "[ROCm/AMD] nunchaku is not available...")

ALWAYS register:
    Krea2ControlNetLoraLoader                         ← nunchaku-independent
    NunchakuQwenImageDiffsynthControlnet              ← nunchaku-independent
```

### 4.1 `__init__.py` — the availability probe and registration gate

**Probe** (module level, before any node import):
```python
try:
    import nunchaku  # noqa: F401
    _NUNCHAKU_AVAILABLE = True
except ImportError:
    _NUNCHAKU_AVAILABLE = False
    logger.warning("[ROCm/AMD] nunchaku is not available...")
```
On AMD the `import nunchaku` raises `ImportError` (the package ships CUDA-only
binaries), so the flag flips to `False` exactly once at startup.

**Registration gate**: the previous single `try: from .nodes.lora.qwenimage import ...`
block (which registered everything together) is split in two:

1. `if _NUNCHAKU_AVAILABLE:` — imports and registers the 7 nunchaku-dependent node
   classes (`NunchakuQwenImageLoraLoader/Stack`, `V1`/`V2`/`V3`,
   `NunchakuZImageTurboLoraStackV1`/`V4`).
2. Unconditional block — registers `Krea2ControlNetLoraLoader`.

The ControlNet node (`NunchakuQwenImageDiffsynthControlnet`) keeps its own separate
`try` block; its Krea2 route only does type checks (`_classify_controlnet_target`) and
never imports nunchaku, so it works on AMD.

**Display-name gate**: the two hardcoded entries in `NODE_DISPLAY_NAME_MAPPINGS` are now
guarded with `**({} if not _NUNCHAKU_AVAILABLE else {...})`, so AMD never exposes
display names for nodes that are not registered (a mismatch ComfyUI could otherwise
report).

### 4.2 `nunchaku_code/lora_qwen.py` — keep the module importable

This module is imported at runtime by every Qwen/Z-Image node (`from
nunchaku_code.lora_qwen import ...`). Its top-level `from nunchaku.lora.flux...`
import would raise `ImportError` on AMD, which would break even unrelated code paths
that merely import the module. The guard:

- On success: `_NUNCHAKU_AVAILABLE = True`, names bound as usual.
- On failure: `_NUNCHAKU_AVAILABLE = False`, and the three converter helpers
  (`pack_lowrank_weight`, `reorder_adanorm_lora_up`, `unpack_lowrank_weight`) are bound
  to `_nunchaku_required`, which raises the descriptive `RuntimeError`. Module import
  itself succeeds, so `_load_lora_state_dict` etc. remain usable for inspection paths.

### 4.3 `wrappers/*.py` — same guard at the wrapper layer

`wrappers/qwenimage.py`, `wrappers/qwenimage_v2.py`, `wrappers/zimageturbo.py` are
loaded lazily via `importlib` from the node code. Each now wraps its top-level nunchaku
imports in `try/except ImportError`, setting `_NUNCHAKU_AVAILABLE` and replacing
`compose_loras_v2` / `reset_lora_v2` with `RuntimeError` raisers on failure. This keeps
`spec.loader.exec_module(wrappers_module)` from crashing with an `ImportError` on AMD.

### 4.4 `nodes/lora/qwenimage*.py` — runtime import guards

Every place that imports `nunchaku` or `nunchaku_code.lora_qwen` at runtime is wrapped:

```python
try:
    from nunchaku import NunchakuQwenImageTransformer2DModel
except ImportError as e:
    raise RuntimeError("nunchaku is required ... but it is not installed or failed to import.") from e
```

`raise ... from e` chains the original `ImportError` as context, so debugging stays
possible while the user-facing message is actionable. On NVIDIA this code path is
identical to before (import succeeds on the first line of the `try`).

### 4.5 Verification Results (virtual AMD test suite)

Because the user cannot test on AMD hardware locally, a virtual test suite simulates
an AMD environment by installing a `sys.meta_path` hook that raises `ImportError` for
any `nunchaku` import, then re-imports the package exactly like ComfyUI does.

| Display names | 2 (no Nunchaku names) | 9 |

**Total: 50/50 checks pass.** The suite also caught a real bug during development:

the display-name gate in 4.1, commit `6f1c2ff`).

### 4.6 Behavior Summary

- **AMD/ROCm**: nunchaku-dependent nodes are not registered; the Krea2 ControlNet
  nodes work. Startup logs `[ROCm/AMD] nunchaku is not available...`.
- **NVIDIA**: identical behavior to v2.5.5 (9 nodes).
- **Legacy workflows**: referencing a disabled node yields a clear `RuntimeError`
  ("nunchaku is required...") instead of an obscure `ImportError`.
