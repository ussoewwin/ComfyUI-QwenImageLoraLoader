# v2.5.8 技术文档：损坏的预编译 LoRA 缓存导致 Windows 致命 "page error" 崩溃的修复

> 修复提交：`cd3ff69` — `fix(cache): read precompiled cache as bytes, not mmap (Windows page error)`
> 日期：2026-08-26

---

## 1. 错误内容

在运行 QwenImage 生成工作流时，ComfyUI 发生硬崩溃 —— 是整个进程崩溃，而不仅仅是节点报错。控制台最后的输出是：

```
[INFO] Requested to load WanVAE
[MultiGPU Issue21] Using non-recursive ModelPatcherDynamic._load_list guard
[INFO] Composing 1 LoRAs (Direct Fix V6)...
[INFO] ⚠️  AWQ Modulation Layer LoRA Injection ENABLED (via override).
Windows fatal exception: page error

Stack (most recent call first):
  File "D:\USERFILES\ComfyUI\python_embeded\Lib\site-packages\safetensors\torch.py", line 359 in load_file
  File "D:\USERFILES\ComfyUI\ComfyUI\custom_nodes\ComfyUI-QwenImageLoraLoader\nunchaku_code\lora_cache.py", line 272 in load_precompiled
  File "D:\USERFILES\ComfyUI\ComfyUI\custom_nodes\ComfyUI-QwenImageLoraLoader\nunchaku_code\lora_qwen.py", line 1411 in compose_loras_v2
```

最后一行是关键特征：

```
Windows fatal exception: page error
```

这**不是 Python 异常** —— 而是 Windows 原生致命错误
（`STATUS_IN_PAGE_ERROR`，进程退出码 `-1073741818` / `0xC0000006`）。
它出现在 `safetensors.torch.load_file` 内部，也就是 `load_precompiled()`
正在读取预编译 LoRA 缓存的时候。由于这是原生崩溃，Python 里任何
`try/except` 都无法捕获，整个 ComfyUI 进程立即终止。

---

## 2. 错误原因

### 2.1 诊断证据

`ComfyUI/models/SVDQLora/` 下的两个预编译缓存文件在磁盘上已损坏：

| 缓存文件 | 读取测试结果 |
|---|---|
| `Qwen-Image-Lightning-8steps-V2.0_d25379dc_precompiled.safetensors` (2.11 GB) | ❌ 崩溃 / `OSError: [Errno 22] Invalid argument` |
| `Qwen-NSFW-Beta5_d25379dc_precompiled.safetensors` (0.68 GB) | ❌ 崩溃 |
| 其余 4 个缓存文件（Asian, InStyle, Qwen-Edit, face_swap） | ✅ 正常读取 |
| `D:\USERFILES\StableDiffusion\models\Lora\qi\quality\` 下的两个源 LoRA 文件 | ✅ 正常读取（2160 / 2520 keys） |

关键观察：

- **源 LoRA 文件完全健康**。损坏的只是*生成的预编译缓存*。
- 损坏文件仍能报告**有效的、可读取的 safetensors 头（元数据）**，但它们的
  **张量数据区在物理上已不可读**（磁盘级损坏 —— 坏扇区之类）。
- 在操作系统层面，即使对数据区做普通顺序读取也会失败，报 `Errno 22`。

### 2.2 为什么是崩溃而不是回退

缓存管线本意是可恢复的：`load_precompiled()` 本来就有
`try/except`，文档也写明「出错时返回空 dict，让调用方优雅地回退到完整
重新融合」。**问题出在读取机制：**

```python
# 修改前（出问题的路径）
from safetensors.torch import load_file as st_load_file
flat = st_load_file(str(cache_path), device="cpu")
```

`safetensors.torch.load_file()` 是**基于 mmap** 的。它把文件映射进进程地址
空间，只在访问张量时才真正触碰对应的内存页。对于损坏文件：

1. 头部页完好 → 元数据解析成功 → 加载器认为缓存有效。
2. 当张量数据区被调入内存时，操作系统无法从磁盘读取 → 内存管理器抛出
   `STATUS_IN_PAGE_ERROR` → **Windows 立即杀死进程**。

`STATUS_IN_PAGE_ERROR` 是以原生故障形式送达的，而不是 Python 异常，所以
`except Exception` 永远不会执行。结果：只要损坏的缓存文件被判定为「有效」，
就会 100% 硬崩溃。

### 2.3 为什么损坏的缓存被判定为有效

`is_cache_valid()` 只检查了**文件存在 + 记录的源文件 mtime**：

```python
if not cache_path.is_file():
    return False
# ... 读取 meta.json，比较 source_mtime ...
return True
```

它**没有对缓存文件内容做任何完整性检查**，因此「头部可读、数据区不可读」
的文件会被当作「最新且可用」。

## 3. 修改后的代码（全文）

### 3.1 修改的代码块 —— 修改前 vs 修改后

**修改前**（`nunchaku_code/lora_cache.py`，位于 `load_precompiled()` 内）：

```python
    try:
        from safetensors.torch import load_file as st_load_file
    except ImportError as exc:
        logger.error(f"[CACHE] Cannot load precompiled cache: safetensors not available. {exc}")
        return {}

    try:
        flat: Dict[str, torch.Tensor] = st_load_file(str(cache_path), device="cpu")
    except Exception as exc:
        logger.error(f"[CACHE] Failed to load {cache_path}: {exc}")
        return {}
```

**修改后**（修复，提交 `cd3ff69`）：

```python
    try:
        from safetensors.torch import load as st_load_bytes
    except ImportError as exc:
        logger.error(f"[CACHE] Cannot load precompiled cache: safetensors not available. {exc}")
        return {}

    try:
        # Read as plain bytes instead of ``load_file`` (mmap). A damaged cache
        # file can still expose a readable header but fail during the mmap'd
        # tensor read, which crashes the whole process with a Windows fatal
        # "page error" that Python cannot catch. A plain read surfaces the same
        # damage as an ordinary OSError, so the existing except below falls
        # back to a full re-fuse gracefully.
        with open(cache_path, "rb") as fh:
            data = fh.read()
        flat: Dict[str, torch.Tensor] = st_load_bytes(data)
    except Exception as exc:
        logger.error(f"[CACHE] Failed to load {cache_path}: {exc}")
        return {}
```

### 3.2 修复后的完整 `load_precompiled()` 函数

```python
def load_precompiled(
    cache_path: Path,
) -> Dict[str, Tuple[torch.Tensor, torch.Tensor, Optional[torch.Tensor]]]:
    """
    Load a precompiled cache file and reconstruct the ``processed_groups`` dict.

    Returns:
        ``{ module_key: (A, B, alpha_or_None) }`` ? identical structure to
        what ``compose_loras_v2`` produces after the classify+fuse stage.
        Returns an empty dict on any error so the caller can fall back to
        a full re-fuse gracefully.
    """
    try:
        from safetensors.torch import load as st_load_bytes
    except ImportError as exc:
        logger.error(f"[CACHE] Cannot load precompiled cache: safetensors not available. {exc}")
        return {}

    try:
        # Read as plain bytes instead of ``load_file`` (mmap). A damaged cache
        # file can still expose a readable header but fail during the mmap'd
        # tensor read, which crashes the whole process with a Windows fatal
        # "page error" that Python cannot catch. A plain read surfaces the same
        # damage as an ordinary OSError, so the existing except below falls
        # back to a full re-fuse gracefully.
        with open(cache_path, "rb") as fh:
            data = fh.read()
        flat: Dict[str, torch.Tensor] = st_load_bytes(data)
    except Exception as exc:
        logger.error(f"[CACHE] Failed to load {cache_path}: {exc}")
        return {}

    # Reconstruct { module_key: { "A": T, "B": T, "alpha": T|None } }
    raw: Dict[str, Dict[str, torch.Tensor]] = {}
    for flat_key, tensor in flat.items():
        # flat_key format:  "<module_key>__<role>"
        # module_key itself may contain dots but never "__"
        sep_idx = flat_key.rfind(_SEP)
        if sep_idx == -1:
            logger.warning(f"[CACHE] Unrecognised flat key format: '{flat_key}' ? skipping.")
            continue
        module_key = flat_key[:sep_idx]
        role = flat_key[sep_idx + len(_SEP):]
        raw.setdefault(module_key, {})[role] = tensor

    processed_groups: Dict[str, Tuple[torch.Tensor, torch.Tensor, Optional[torch.Tensor]]] = {}
    for module_key, parts in raw.items():
        A = parts.get(_ROLE_A)
        B = parts.get(_ROLE_B)
        alpha_tensor = parts.get(_ROLE_ALPHA)  # 1-D float32 scalar tensor or None

        if A is None or B is None:
            logger.warning(f"[CACHE] Incomplete entry for '{module_key}' (missing A or B) ? skipping.")
            continue

        # Convert alpha back to the same form compose_loras_v2 expects:
        # a torch.Tensor scalar (not a Python float).
        alpha: Optional[torch.Tensor] = None
        if alpha_tensor is not None:
            alpha = alpha_tensor  # keep as tensor; compose_loras_v2 calls .item() on it

        processed_groups[module_key] = (A, B, alpha)

    logger.info(f"[CACHE LOAD] Loaded {len(processed_groups)} module entries ← {cache_path.name}")
    return processed_groups
```

## 4. 代码的含义 / 为什么能修复崩溃

### 4.1 `from safetensors.torch import load as st_load_bytes`

我们从 `load_file`（mmap 支撑）切换到 `load`（bytes 支撑）：

- `load_file(path)` 将文件内存映射，并在访问张量时按需调入内存页 →
  损坏的数据区会触发*无法捕获的原生页面错误*。
- `load(bytes)` 解析的是已经放在内存里的 Python `bytes` 对象；
  完全不涉及 mmap。

### 4.2 `with open(cache_path, "rb") as fh: data = fh.read()`

整个缓存文件用**普通顺序读取**代替 mmap。
这把失败模式从「原生页面错误」变成**普通的 Python `OSError`**：

- 健康文件：正常读完，行为没有区别。
- 损坏文件：系统读取碰到坏死区域，抛出
  `OSError: [Errno 22] Invalid argument` —— 一个*普通 Python 异常*，可以被外层
  `try/except Exception` 捕获。

内存说明：2 GB 缓存在解析前会临时占用约 2 GB 主机内存作为 `bytes`，
在典型工作站上完全可以接受，而且远比进程硬崩溃划算。

### 4.3 既有的 `except Exception` 现在真正生效了

```python
    except Exception as exc:
        logger.error(f"[CACHE] Failed to load {cache_path}: {exc}")
        return {}
```

因为失败现在以 Python 异常形式到达，这段代码在损坏缓存上第一次真正执行。
它记录错误并返回**空 dict** —— 这正是 `load_precompiled()` 的文档约定。
调用方（`lora_qwen.py` 中的 `compose_loras_v2`）随即回退到对源 LoRA 做
**完整重新融合**。新融合的结果通过 `save_precompiled()` 重新保存
（用 `os.replace` 替换 `.tmp` 文件），用健康缓存覆盖损坏缓存。
系统可以自愈：不需要手动删除，也不会反复崩溃。

### 4.4 为什么 `is_cache_valid()` 保持不变

`is_cache_valid()`（文件存在 + mtime 边车文件）是廉价的快速路径检查。
如果在那里加入完整的数据完整性扫描，每次缓存校验都要读完整文件，
反而失去缓存的意义。把修复放在 `load_precompiled()` 里，损坏文件会在
*加载时* —— 也就是真正需要其内容的唯一时刻 —— 被捕获，快速路径仍然廉价。

## 6. 操作说明

- 受影响机器上两个损坏的缓存已改名为
  `*.safetensors.broken`（以及对应的 `.meta.json.broken`），
  这样加载器会判定它们无效，并在下次启动时从健康的源 LoRA 重新生成。
- 没有任何源 LoRA 文件被修改或重新下载 —— 损坏仅限于*生成的*缓存产物。
- 如果以后再次遇到这类崩溃（任何 safetensors mmap 加载），
  同样适用「按字节读取」的修复模式。

---

## 7. LoRA 功能完全保留——这不是"禁用 LoRA"的修复

本次修复**只改变了预编译缓存文件的读取方式**（基于 mmap 的 `load_file` → 普通字节读取 + `safetensors.load`）。它**不会**禁用、跳过、削弱或以任何方式改变 LoRA 的行为：

- 两种读取路径解析的是完全相同的文件字节，因此每个融合后的 LoRA 权重（`A`、`B`、`alpha`）都以逐位相同的值加载。已用 `InStyle-0.5` 缓存实测：新旧读取路径下全部 **1200 个张量**完全一致（每个 key 都通过 `torch.equal`；无 dtype / shape / 值差异）。
- 返回的 `processed_groups` 字典——也就是 `compose_loras_v2()` 实际用于应用 LoRA 的数据——与修复前完全一致。下游的 LoRA 注入 / modulation 逻辑完全未动。
- **健康缓存**：加载行为完全相同，LoRA 结果完全相同。
- **损坏缓存**：旧代码会让整个 ComfyUI 进程崩溃（Windows 致命 page error），根本*无法生成任何图片*；新代码则回退到从原始源 LoRA 完整重新融合，LoRA 仍会正确应用——融合结果还会作为健康缓存重新保存。

简言之：本次修复让 LoRA 在所有场景下保持完整可用；它只是把致命崩溃变成了优雅恢复。
