# v2.6.0 技术文档：节点改名、明确支持范围与标准 Qwen Image 路由修复

> 修复提交：`e347fc6` - `Update node display name, README docs, and add diffsynth node image`

## 概述

本次发布：

1. **重命名** ControlNet 节点：`NunchakuQI&ZITDiffsynthControlnet` -> **`Nunchaku ZI Diffsynth Controlnet&Krea2 LoRA ControlNet`**（内部类名 `NunchakuQwenImageDiffsynthControlnet` 不变，已有工作流无需修改即可加载）。
2. **明确各路由的支持范围**（ZI / QI / Krea2）。
3. **修复路由分类**：标准（非 Nunchaku）`QwenImageTransformer2DModel` 现被正确路由到 `qwenimage_standard` 路径，不再因 `unknown` 而报错。

## 1. 节点改名

| 之前 | 之后 |
|------|------|
| `NunchakuQI&ZITDiffsynthControlnet` | **`Nunchaku ZI Diffsynth Controlnet&Krea2 LoRA ControlNet`** |

- **内部类名**：`NunchakuQwenImageDiffsynthControlnet`（不变）。
- **工作流兼容性**：已保存的工作流仍可加载，因为类名是稳定标识符。
- 旧名称有误导性：它暗示该节点支持 "Nunchaku Qwen Image"，但 DiffSynth 路由**不适用于** Nunchaku Qwen Image。新名称反映了实际能力：Z-Image-Turbo（ZI）DiffSynth ControlNet + Krea2 LoRA ControlNet。

---

## 2. 明确支持范围

该节点有三个路由，每个路由的模型支持范围严格定义：

### Z-Image-Turbo（ZI 路由）
- 支持 **Nunchaku**（量化）Z-Image-Turbo 模型**以及**所有非量化 / 量化 Z-Image 模型。
- 示例：`svdq-fp4_r128-z-image-turbo.safetensors`（Nunchaku）+ `Z-Image-Turbo-Fun-Controlnet-Union` 模型补丁。

### Qwen Image（QI 路由）
- 支持所有**非 Nunchaku** 的 Qwen Image 模型：
  - **非量化**：标准 bf16 / fp16 Qwen Image 模型（如 `qwnImageEdit_v16Bf16.safetensors`）。
  - **量化**：HSWQ ConvRot INT8 模型（如 `qwnImageEdit_v16Bf16_convrot_int8.safetensors`）。
- **Nunchaku Qwen Image 不受支持**。技术原因见第 4 节。

### Krea2 路由（depth / openpose）
- 不变，通过 `Krea2ControlNetLoraLoader` 的完全隔离路由（`krea2-depth-control-lora.safetensors` / `krea2_turbo_openpose_controlnet.safetensors`）。

## 3. 路由分类修复

`_classify_controlnet_target` 现在能识别标准（非 Nunchaku）扩散模型类：

```python
if dm_name in ("ComfyQwenImageWrapper", "NunchakuQwenImageTransformer2DModel", "QwenImageTransformer2DModel"):
    return "qwenimage_standard"
```

**修复前**：标准 bf16 Qwen Image 模型（`QwenImageTransformer2DModel`）落入 `unknown`，抛出 `RuntimeError` 并中断工作流。

**修复后**：正确路由到 `qwenimage_standard`，使用标准 ComfyUI `patches["double_block"]` 路径 - 与 ComfyUI 参考实现 `QwenImageDiffsynthControlnet` 节点相同的机制。这使得 `qwen_image_canny_diffsynth_controlnet_convrot_int8.safetensors` 等可通过 `Model Patch Loader`（`ModelPatchLoaderCustom`）+ 本节点在标准 bf16 Qwen Image 模型上正常工作。

---

## 4. 技术背景：为何 Nunchaku Qwen Image 与 DiffSynth 路由不兼容

调查表明，问题**不在** ControlNet 模型本身（`QwenImageBlockWiseControlNet` 的解码是正确的），而在于 **nunchaku W4A4 量化 Qwen Image 模型的内部 hidden-state 尺度**：

- nunchaku 的 `SVDQW4A4Linear`（W4A4，激活也被量化）会在每个 transformer 块内放大 hidden-states（实测：`to_qkv` 约 29 倍、MLP 约 760 倍放大；块输出均值约 1.4e5，而 Z-Image 保持在标准尺度约 0.3-5）。
- hidden-states 还具有严重的**逐通道尺度不均匀**（通道 RMS 差异最高约 1500 倍），由 W4A4 分组尺度的累积造成。
- BlockWise ControlNet（`QwenImageBlockWiseControlNet`）是针对**标准尺度** hidden-states 训练的。其残差仅占 nunchaku hidden-state 幅度的约 0.3%，因此控制效果实际上不可见；直接对残差重缩放会破坏通道结构并产生坏图。
- Z-Image 不受影响，因为它的 nunchaku 实现（`NextDiT`）将 hidden-states 保持在标准尺度。

**结论**：QI 路由请使用标准（非 Nunchaku）bf16 Qwen Image 模型；ZI 路由使用 Nunchaku Z-Image-Turbo 可正常工作。这是 nunchaku Qwen Image 的限制（类似上游 issue #711），并非 ControlNet 模型本身的缺陷。
