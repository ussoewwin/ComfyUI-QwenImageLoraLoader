# v2.6.3 技术文档：SAM3 分割头 FPN 层级裁剪补丁（空掩码修复）

## 概述

本版本新增 **SAM3（Segment Anything 3）非 multiplex 检查点的上游兼容补丁**：`patches/sam3_seg_features_scalp_patch.py` 修复使用文本提示运行时产生的**空 / 接近全黑掩码**问题。根本原因是 ComfyUI 核心在 `SAM3Detector._detect` 中的缺陷；本补丁在不改动 ComfyUI 安装的前提下，应用与 [Comfy-Org/ComfyUI PR #15979](https://github.com/Comfy-Org/ComfyUI/pull/15979) 相同的修复。

## 1. 问题现象

- 检测分数正确（top-1 ≈ **0.98**），但输出掩码几乎全黑（>0 比例 ≈ **0.35%**），而非干净的白色剪影（预期 ≈ **59%**）。
- 受影响：SAM3（非 multiplex）检查点，例如 `sam3_convrot_int8.safetensors`。SAM3.1（multiplex）不受影响。

## 2. 根本原因

- ComfyUI 的 `SAM3Detector._detect()` 在应用裁剪（`features = features[:-self.scalp]`）**之前**捕获 `seg_features = features`。
- SAM3（非 multiplex）有 **4 个 FPN 层级**（288 / 144 / 72 / 36 px），`scalp=1` 使编码器使用 **3 个层级** —— 但 `SegmentationHead` 收到**全部 4 个**。
- `SegmentationHead.forward` 将 `backbone_features[-1]`（36 px 层级）替换为 `encoder_visual`，后者由 `memory` 的前 `36 * 36 = 1296` 个 token 构建 —— 而 `memory` 包含 **5184** 个图像 token（72 x 72）。36 px 裁剪与该层级的真实空间布局**不对应**，破坏了像素解码器并使所有掩码 logit 强烈偏向负值（空掩码）。
- SAM3.1（multiplex，`scalp=0`）不受影响：裁剪分支被跳过。

## 3. 修复（本补丁）

- `apply_sam3_seg_features_scalp_patch()` 包装 `SAM3Detector._detect`：
  - **预裁剪** `features` / `positions`，并在调用原始 `_detect` 时**临时将 `self.scalp` 设为 0**，使 `seg_features` 与编码器保持相同的 **3 个层级**。72 px 层级随后接收完整的 5184-token `encoder_visual`，空间布局正确。
- 在 ComfyUI 启动时自动应用（在 `__init__.py` 中注册）。
- **上游修复合并后自动失效**（PR #15979）—— 包装器预裁剪后，已修复的原始函数保持 `seg_features` 不变，因此不会重复应用。
- 对 multiplex 模型（SAM3.1，`scalp=0`）为**无操作** —— 包装器直接透传。

## 4. 新增 / 修改文件

- `patches/sam3_seg_features_scalp_patch.py`（新增）
- `__init__.py`（启动时自动应用）

## 5. 验证

- 回退 ComfyUI 核心修复 + 仅应用本补丁：
  - top-1 分数：**0.9863**
  - 掩码 >0 比例：**59.4%**（与 SAM3.1 参考输出一致）
- 对 SAM3.1 / 图像生成模型无影响。
