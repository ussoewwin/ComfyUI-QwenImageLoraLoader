## ① 问题所在

### 1.1 概要

新版 ComfyUI 前端（ComfyUI_frontend）现在会把节点上的部件“采用（adopt）”为具象部件类，**保持对象同一性但替换部件的 prototype**。V1 节点脚本用 `w instanceof NunchakuLoraWidget` 判断“这一行是不是我的”；采用之后该判定恒为 `false`，因此四项交互停止工作。

### 1.2 机制（逐条对应源码）

1. 节点构造时，前端调用 `initializeWidgetsView(this)`（`src/lib/litegraph/src/LGraphNode.ts:1048`）。
2. 该调用把 `node.widgets` 重定义为取值器，返回 `state.view`，而 `state.view` 是 `createArrayMutationView(target, ...)` 生成的 **Proxy**（`src/lib/litegraph/src/node/widgetsView.ts`、`src/lib/litegraph/src/infrastructure/createMutationView.ts`）。
3. 数组的变更方法（`copyWithin` / `fill` / `pop` / `push` / `reverse` / `shift` / `sort` / `splice` / `unshift`）或整体赋值会触发 commit，进而调用 `syncWidgetOrder(node, widgets)`：

```ts
// src/lib/litegraph/src/node/widgetsView.ts (excerpt)
function syncWidgetOrder(node: LGraphNode, widgets: IBaseWidget[]): void {
  node._widgetSlotsDirty = true
  const graphId = node.graph?.rootGraph.id
  for (const [index, widget] of widgets.entries()) {
    const concreteWidget = toConcreteWidget(widget, node)   // wrapLegacyWidgets defaults to true
    widgets[index] = concreteWidget
    if (graphId) concreteWidget.setNodeId(node.id)
  }
  ...
}
```

4. `toConcreteWidget` 对已知 type 会实例化对应的具象类；对 `type === "custom"`（本插件的 `NunchakuLoraWidget.type`）落到 `default` 分支，被包装为 `LegacyWidget`（`src/lib/litegraph/src/widgets/widgetMap.ts:205-280`）。
5. 决定性的部分是 `adoptConcreteWidget`：它**不是**用新对象替换，而是**原地采用**（同文件 139-175 行）：

```ts
function adoptConcreteWidget<C extends BaseWidget>(widget: IBaseWidget, concrete: C): C {
  if (concrete === widget || !Object.isExtensible(widget)) return concrete
  const rawOptions = widget.options
  const descriptors = collectDescriptors(concrete)
  const foreignDescriptors = collectDescriptors(widget)
  for (const [key, foreignDescriptor] of foreignDescriptors) {
    if (key === 'options') continue
    const descriptor = mergeDescriptor(descriptors.get(key), foreignDescriptor,
      Object.getOwnPropertyDescriptor(widget, key))
    if (key === 'disabled' && foreignDescriptor.get) descriptor.get = foreignDescriptor.get
    descriptors.set(key, descriptor)
  }
  preserveHiddenFacade(descriptors, foreignDescriptors)
  if (Reflect.ownKeys(widget).some((key) => descriptors.has(key) &&
        Object.getOwnPropertyDescriptor(widget, key)?.configurable === false) ||
      !Reflect.setPrototypeOf(widget, Object.getPrototypeOf(concrete)))
    return concrete
  Object.defineProperties(widget, Object.fromEntries(descriptors))
  const adopted = widget as unknown as C
  if (adopted instanceof BaseWidget) adopted.options = rawOptions
  return adopted
}
```

换言之：**同一个对象**，其 prototype 经 `Reflect.setPrototypeOf` 被替换，具象类的成员被作为 own 属性写入。因此：

- 引用不变：`node.widgets` 的元素以及插件持有的任何引用仍指向同一对象；
- `Object.getPrototypeOf(widget)` 已不再是 `NunchakuLoraWidget.prototype`，所以 `w instanceof NunchakuLoraWidget === false`。

6. 之后任何一次 commit，`instantiateConcreteWidget` 因 `widget instanceof BaseWidget` 直接返回该对象（同文件 210-211 行），使 `concrete === widget`；采用因此成为幂等操作，不会再次改写描述符。

## ⑤ 其含义

### 5.1 为什么 `loraWidgets` 是正确的身份契约

- 行的创建点是 `addLoraRow`：它执行 `new NunchakuLoraWidget(name, this)`，随后 `this.widgets.splice(btnIdx, 0, w)` 与 `this.loraWidgets.push(w)`。因此 `loraWidgets` 保存的正是 `widgets` 中的**同一批对象**。
- 采用是原地进行的（`Reflect.setPrototypeOf` + `defineProperties`），对象同一性得以保留，所以 `loraWidgets.includes(x)` 与对象同一性判断始终一致。
- 相反，`instanceof` 依赖前端内部实现（prototype 是否被替换）。这是一种**对外部实现细节的脆弱依赖**，也正是上游报告（[#17817](https://github.com/Comfy-Org/ComfyUI_frontend/issues/17817)）的共同根因。

### 5.2 `this` 绑定的等价性（逐处核对）

| 位置 | 调用方式 | 结果 |
|---|---|---|
| `getSlotInPosition` | `LGraphCanvas.ts:8775` 以 `node.getSlotInPosition(...)` 调用 | `this` = 该节点 |
| `getSlotMenuOptions` | `LGraphCanvas.ts:8780` 以 `node.getSlotMenuOptions(slot)` 调用 | `this` = 该节点 |
| `moveLora` | 由菜单回调以 `this.moveLora(widget, ±1)` 调用（箭头函数继承 `this`） | `this` = 该节点 |
| `onConfigure` | `onConfigure?.apply(this, arguments)` | `this` = 该节点 |

### 5.3 本次未修改、且不受采用影响的部分（实测）

- **自绘 `draw`**：`BaseWidget` 与 `LegacyWidget` 都没有实现 `draw`，而采用会把原对象的描述符（含 `draw`）保留为 own 属性。绘制入口 `LGraphNode.drawWidgets`（4200 行起）会设置 `widget.last_y = y`（4218 行）并调用自前 `draw`（4243-4244 行）。
- **自前 `mouse` 处理**：`LGraphCanvas.processWidgetClick` 先尝试 `toConcreteWidget(widget, node, false)`；对已被采用的对象该调用返回 `undefined`，于是走 `widget.mouse(...)`（3078 行）这条旧路径。开关、强度加减、选择 LoRA 的既有点击行为不变。
- **保存**：`serialiseWidgetValues`（`LGraphNode.ts:184-196`）读取 `widget.value`。采用后 `value` 变为 `BaseWidget` 的访问器，但其 `_state.value` 仍指向原对象，因此序列化结果不变（LoRA 行仍写入 `widgets_values`）。
- **恢复**：`onConfigure` 依 `info.widgets_values` 重建行；本次修改让“先清除”这一步真正生效，从而消除重复行。

### 5.6 剩余约束与将来风险

1. 该修正依赖“采用保持对象同一性”。若今后给 `NunchakuLoraWidget` 加上 `Object.freeze`/`seal` 或不可配置属性，`adoptConcreteWidget` 会退回为返回新对象，`loraWidgets` 的成员判定就会**静默失效**。
2. `getSlotInPosition` 在 `LGraphNode` 侧已被标记 `@deprecated`（替代 API 为 `getSlotOnPos`）。现行 `main` 仍走旧路径，但一旦切换，本插件的右键机制需要重新实现。
3. 根本修正属于上游（[#17817](https://github.com/Comfy-Org/ComfyUI_frontend/issues/17817)）。在正式 API 出现之前，本 PR 的做法（把节点自身的实时数组用作身份契约）是当前可用的正确方案。
