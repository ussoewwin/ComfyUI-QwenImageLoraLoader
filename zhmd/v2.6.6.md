## 1. 变更内容与原因

### 1.1 背景：该守卫为何存在

rgthree-comfy 会通过自己的路由（`/rgthree/logo*.svg`）提供节点 logo。本包在 v2.6.4 中添加了自防御守卫 `patches/rgthree_logo_route_guard.py`，原因是 rgthree 会对抓取到的标记内容执行 `str.format()`：

```python
# rgthree-comfy/py/server/routes_config.py（上游修正前）
async def get_logo(...):
    svg = await get_logo_svg()
    resp = svg.format(bg=bg, fg=fg)
```

当抓取到的内容不是 SVG（代理、强制门户或 CDN 错误页）时，`svg.format(...)` 会对每个请求抛出 `ValueError: unexpected '{' in field name`，而且这份损坏内容会被缓存直到重启。

### 1.2 为何现在不再需要

由 ussoewwin 提交的上游修正 **rgthree-comfy#763**（“fix(logo): don't let a non-SVG / proxy error response break the logo route”）已被合并（2026-09-25）。它修改了 `py/server/routes_config.py`（+6/−1）与 `py/pyproject.py`（+22/−2），使路由不再对非 SVG 内容执行格式化。

本机安装的 rgthree-comfy 已包含该修正（提交 `17f1848 fix(logo): don't let a non-SVG / proxy error response break the logo route`，已并入其 `main`），因此本包中的该守卫已成为冗余。
