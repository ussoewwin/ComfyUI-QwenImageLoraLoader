## 1. 变更内容与原因

### 1.1 背景：ComfyUI v0.38 引入的 `fast_disk`

ComfyUI v0.38 起，fast-disk（aimdo 虚拟显存）成为所有模型加载器的默认能力。`ModelPatcher.clone()` 在重新实例化 patcher 类时无条件传入新参数：

```python
# comfy/model_patcher.py (v0.38.x, clone())
n = class_(model_override[0], self.load_device, self.offload_device, self.model_size(),
           weight_inplace_update=self.weight_inplace_update, fast_disk=self.fast_disk)
```

基类 `ModelPatcher.__init__` 已声明 `fast_disk=False`，但子类 `ZImageModelPatcher` 的签名没有跟上。

### 1.2 症状

ComfyUI-nunchaku（上游已停止开发）的 `model_patcher/zimage.py`：

```python
class ZImageModelPatcher(ModelPatcher):
    def __init__(self, model, load_device, offload_device, size=0, weight_inplace_update=False):
        super().__init__(model, load_device, offload_device, size, weight_inplace_update=False)
        self.svdq_backup = {}
```

任何对 nunchaku Z-Image 模型执行 `model.clone()` 的节点（例：采样链路中的 EasyCache 节点）都会抛出：

```
TypeError: ZImageModelPatcher.__init__() got an unexpected keyword argument 'fast_disk'
```

失败的 clone 还会在对象 GC 时连带产生次生异常 `AttributeError: 'ZImageModelPatcher' object has no attribute 'pinned'`（半成品对象走到 `__del__ → unpin_all_weights`）。

## 2. 修复：内存运行时包装（nunchaku 本体 100% 不动）

`patches/nunchaku_patch.py` 新增 `apply_nunchaku_zimage_fast_disk_patch()`：

- 用包装器替换 `ZImageModelPatcher.__init__`：接受 `fast_disk` 关键字并转发存储（`self.fast_disk = ...`），其余参数原样透传给原 `__init__`。
- **幂等**：包装器带 `_qwen_lora_loader_zimage_fast_disk_patch` 标记，重复调用直接短路。
- **面向未来安全**：若某未来的 nunchaku 版本已在签名中声明 `fast_disk`，补丁自动 no-op。
- **仅通过 `sys.modules` 扫描定位类，绝不重新 import**：ComfyUI 以 `custom_nodes.ComfyUI-nunchaku.model_patcher.zimage` 之类的包名加载节点包，另行 import 会产生第二个模块实例，补丁就打在一个没人用的类上。
- **加载顺序竞态**：本包常因文件夹名顺序早于 nunchaku 加载；补丁与既有的 fuse-patch 共用同一个重试定时器（0.25s × 24 次），nunchaku 模块出现后立即生效。
- 入口不变：随 `apply_nunchaku_patch()`（本包 `__init__.py` 调用）执行，与 rotary shim、lazy Linear、copy_params 补丁并列。

## 4. 实测验证

* 独立构造测试：补丁应用前 `fast_disk` 参数不存在 → 应用后按 v0.38 `clone()` 的调用形式（位置参数 + `weight_inplace_update=` + `fast_disk=True`）构造成功，`fast_disk` 正确保存，`svdq_backup`、`pinned` 完好。
* 旧式调用（不传 `fast_disk`）不受影响，默认 `False`。
* 幂等：重复调用返回成功且不二次包装。
* 真实端到端：ComfyUI v0.38.1 + HSWQ ConvRot NVFP4 UNet + INT8 ConvRot ControlNet（180 个运行时 patch）+ EasyCache 的完整混合工作流跑通（7/7 与 5/5 采样全部完成，无异常）。

## 5. 需要用户做什么

* 通过 ComfyUI Manager / git pull 更新本包到 v2.6.7，重启 ComfyUI。
* 无需修改任何工作流或 nunchaku 文件。
