本文件记录一项变更：v2.7.0 恢复用于消除 `[ERROR] ... loss/logits ... but not documented` 的预防性补丁。该行由 `transformers` 在导入 Qwen3-VL / Qwen2.5-VL 的 modeling 时打印。补丁在 v2.6.9 中被删除；之所以恢复，是因为那次删除的依据只对 transformers 5.23.0 及之后成立。

## 1. 本版本改了什么

| 项目 | 内容 |
| --- | --- |
| 恢复的文件 | `patches/transformers_qwen_vl_docstring_patch.py`（248 行，blob `7751b492f53c`） |
| 恢复的接线 | `prestartup_script.py`（+15 行：1 个常量、14 行块） |
| 版本 | `pyproject.toml` 与 `__init__.py` 由 `2.6.9` 升至 `2.7.0` |
| changelog | `RELEASE_NOTES/changelog.md` 与 `zhmd/changelogzh.md` 的 v2.7.0 条目 |
| tag | `v2.7.0`（annotated），提交 `c7804f3` |

v2.6.9 不撤回。它的 tag（`e4490e3`）、发布页与 changelog 条目保持原样；v2.6.7、v2.6.8 亦不受影响。两个版本是同一决定的两面：v2.6.9 依据 transformers 5.23.0 的实测删除了补丁，v2.7.0 把补丁还给那次实测未覆盖的环境。

## 2. 为什么恢复

### 2.1 旧版 transformers 仍会打印该行

被删除的补丁记录了机理：Qwen VL 的 modeling 声明自己的 causal-LM 输出类，继承 `CausalLMOutputWithPast`，并通过共享的 `ModelOutputArgs` 参数块合并父类文档。`ModelOutputArgs` 不含 `loss` 与 `logits`，合并后有两个标注未获文档说明，校验器便在导入下列模块时打印两行 `[ERROR]`：

- `transformers.models.qwen3_vl.modeling_qwen3_vl`
- `transformers.models.qwen2_5_vl.modeling_qwen2_5_vl`

没有任何东西失败，推理不受影响。损害在日志：每次加载 Qwen VL 文本编码器的启动，都会带上两行「预期内错误」。

### 2.2 v2.6.9 的依据覆盖到哪里

删除的依据是对 transformers 5.23.0 的实测：该版本在这两个 modeling 中已完全不使用 `ModelOutputArgs`。`qwen3_vl` 直接返回 `CausalLMOutputWithPast`（标注 L1298、构造 L1363），唯一的自定义输出类是 `BaseModelOutputWithDeepstackFeatures`（普通 dataclass）。在无补丁状态下导入两个 modeling，stdout 与 stderr 的 `[ERROR]` 均为 0 行。

该结论正确且仍然成立。它没有覆盖的是所有更早的版本——那些版本仍会合并父类文档，该行仍会打印。

### 2.3 受影响的人

使用旧版 `transformers` 的用户——随包内置 5.15.x 的可携版 ComfyUI，或被其他自定义节点固定版本的环境——仍会看到这两行。本版本正是为他们存在。在 5.23.0 及之后，恢复的补丁会经实测判定不安装任何东西。

## 3. 补丁做什么

补丁包装 `transformers.utils.auto_docstring.get_args_doc_from_source`，针对 `ModelOutputArgs` 把从 `CausalLMOutputWithPast.__doc__` 解析出的 `loss` 与 `logits` 条目合并回去。是否安装包装由两道门决定：

1. 原生门 —— `ModelOutputArgs` 是否已在文档中给出 `loss` 与 `logits`；
2. 导入门 —— 以子进程导入两个 modeling，捕获 stdout，统计同时含 `[ERROR]` 与 `loss` / `logits` 的行。

| 环境 | 门 1 | 门 2 | 结果 |
| --- | --- | --- | --- |
| transformers 5.23.0 及之后 | False（字段仍缺） | True（导入干净） | **不**安装包装，行为不变 |
| 低于 5.23 | False | False（出现该行） | 在 modeling 导入前安装包装，阻止该行 |
| 探测无法执行（超时、非零退出） | False | None | 安装包装（安全方向） |

包装带标记、幂等，不会重复包装。它由 `prestartup_script.py` 执行，早于任何 custom node 的 `__init__`——因为 ComfyUI-nunchaku 会在本包的 `__init__.py` 之前导入其 `models/qwenimage.py`。

## 4. 成本

在 transformers 5.23.0 上补丁走跳过分支，但探测已经执行：每次 ComfyUI 启动都会启动一次子进程导入两个 modeling。开发机实测该调用 **29.82 秒**。这笔成本是有意接受的——它换来对旧环境的有效防护，且无需固定 `transformers` 版本；这也正是 v2.6.9 试图回避、本版本重新接受的成本。

## 6. 何时可以再次删除

判据是版本，而不是意见：当受支持的最低 `transformers` 达到 5.23 或更高时删除。届时支撑 v2.6.9 的那次实测将适用于所有受支持环境，`git revert 811b226` 会同时移除文件与接线。在那之前删除，就等于让旧版用户得到一个带两行预期错误的日志——这正是 v2.6.9 到本版本之间发生的事。
