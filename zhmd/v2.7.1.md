本文件记录一项变更：ComfyUI prestartup 阶段执行的任何代码都不再导入 `torch`，因此 `main.py` 不再打印

```
WARNING: Potential Error in code: Torch already imported, torch should never be imported before this point.
```

涉及两个节点包：本仓库（`ComfyUI-QwenImageLoraLoader`）与 `ComfyUI-HSWQ-Loader-and-Tools`。两者都在下文说明。

## 1. 问题是什么

### 1.1 症状

每次 ComfyUI 启动，"Prestartup times for custom nodes" 区块之后几秒都会打印上面那行警告。没有任何东西失败：服务正常启动、模型正常加载、图片正常生成。该行是 ComfyUI 自身的诊断输出，不是节点抛出的错误。

代价是每次启动都带一条诊断噪声——更糟的是，它让启动日志失去信号价值：真正的提前导入问题会与它长得一模一样。

### 1.2 此前做过什么

commit `9e30661`（2026-07-21，"fix: suppress cosmetic Torch already imported warning in prestartup"）在 root logger 上挂了一个 `logging.Filter`：

- 过滤器匹配子串 `Torch already imported`；
- 第一条匹配记录被丢弃（`return False`），之后的记录全部放行；
- 环境变量 `QWENIMAGE_SUPPRESS_TORCH_WARNING` 可以关闭该过滤器。

实测效果：装上过滤器后，警告从日志里消失，但 `torch` 仍在 prestartup 期间被导入。也就是说，机制隐藏了症状，原因原封不动。而且过滤器挂在 root logger 上，连其他节点的同一条警告也一并隐藏了。

### 1.3 在本机实际观测到什么

| 状态 | 启动日志中 `Torch already imported` 的行数 |
| --- | --- |
| v2.7.0（过滤器生效，两个节点都在导入 torch） | 0 行（被抑制） |
| 移除过滤器、只修复本包 | 1 行 |
| 移除过滤器、本包与 HSWQ 都已修复 | 0 行 |

中间一行是关键：移除过滤器、只修复本包之后，警告仍然被打印，因为另一个节点在 prestartup 顺序中更早导入了 `torch`。修一个节点不等于修好。

## 2. 本质原因

### 2.1 ComfyUI 在哪里判定

`main.py`，按执行顺序：

| 行 | 语句 |
| --- | --- |
| 254 | `execute_prestartup_script()` |
| 262 | `if 'torch' in sys.modules:` |
| 263 | `logging.warning("WARNING: Potential Error in code: Torch already imported, ...")` |
| 266 | `import comfy.utils` |
| 272 | `import nodes`（自定义节点加载） |
| 296 | `comfy_aimdo.control.init_devices(...)` |

判定只是对 `sys.modules` 的一次成员检查。任何在 262 行之前导入 `torch` 的东西都会触发它——包括 `comfy.*` 模块，因为 `comfy.memory_management` 第一行就是 `import torch`。判定在所有 `prestartup_script.py` 之后执行，所以一个节点就足够了。

### 2.2 触发源一：本包的 rotary 兼容垫片

`patches/nunchaku_patch.py` 在模块级别 `import torch`（第 10 行），而该模块由 `prestartup_script.py` 加载。仅加载模块就把 `torch` 放进了 `sys.modules`：

```
before= False  after= True
```

rotary 兼容函数还会在 prestartup 期间 `import comfy.ldm.qwen_image.model` 以判断是否需要把 `apply_rope1` 别名过去。该导入同样会拉入 `torch`。调用后实测：`torch=True comfy=True`。

垫片本身有真实原因：ComfyUI 在 `6e1ef2311b` 中移除了 `comfy.ldm.qwen_image.model.apply_rotary_emb`，而 ComfyUI-nunchaku 仍在导入它，所以该符号必须在 nunchaku 的模块被导入之前存在。这就是该项工作原本放在 prestartup 的原因。

### 2.3 触发源二：HSWQ 的 fast-disk 支持

`ComfyUI-HSWQ-Loader-and-Tools/prestartup_script.py` 在模块级别调用 `_install_fastdisk_support()`。该函数加载 `patches/comfy_aimdo_fastdisk_guard.py` 并应用它，而应用过程会导入 `comfy.memory_management`（`patches/comfy_aimdo_fastdisk_guard.py` 的 `_patch_mem_slice`）以及各 `comfy_aimdo` 模块。`comfy/memory_management.py` 第 4 行是 `import torch`。

首次 `torch` 导入的调用栈（实测）：

```
torch
  <frozen importlib._bootstrap>: _load_unlocked / exec_module
  comfy/memory_management.py:4
  ComfyUI-HSWQ-Loader-and-Tools/prestartup_script.py: (the __import__ hook line)
```

其余 prestartup 脚本实测不导入 `torch`：

| 节点 | 其 prestartup 之后 |
| --- | --- |
| `rgthree-comfy` | `torch=False comfy=True` |
| `comfyui-easy-use` | `torch=False comfy=True` |
| `ComfyUI-Legacy-Tools` | `torch=False comfy=False` |
| `ComfyUI-Manager` | `torch=False comfy=True` |

### 2.4 为什么不能直接删掉这两处调用

两处 prestartup 工作都出于顺序要求，而它们保护的不是 ComfyUI 那条警告关心的顺序：

- **rotary 别名**：nunchaku 在*它自己的*模块被导入时读取 `apply_rotary_emb`。别名必须已经就位，因此不能推迟到自定义节点加载之后。它只需要在*n那次读取之前*生效，而不需要在 ComfyUI 判定之前生效。
- **fast-disk guard**（`patches/comfy_aimdo_fastdisk_guard.py` 的 docstring）：comfy-aimdo 按设计是单线程的——`g_devctx` 是线程局部的，原生 reader 只有一个完成槽（前一次读取必须 retire 后下一次才能激活），stream 解析使用调用线程的 current stream。ComfyUI v0.38 的异步卸载／并行加载／预取会从多个线程驱动这些调用，因此 guard 让所有原生调用在调用线程上内联执行、用进程级 `RLock` 串行化、在页映射之前与设备目的地拷贝之后做同步（CUDA graph 捕获期间绝不同步），并把读取失败转成可恢复的 `False`，让 ComfyUI 的 mmap 回退接管数据而不是中止。因此 guard 必须在任何 aimdo 调用之前、`init_devices` 之前安装。

删掉任何一处都会去掉保护。修复必须把*生效时机*移到 `main.py:262`（判定）与 `main.py:296`（`init_devices`）之间的窗口里，同时不在判定之前导入 `torch`。

### 2.5 两者采用的机制

一个导入钩子（`sys.meta_path` finder，或既有的 `builtins.__import__` 钩子），自身不做任何导入，只在目标模块被加载的瞬间执行工作：

- 本包：拦截 `comfy.ldm.qwen_image.model`，包装其 loader，在模块执行完的 `exec_module` 中装上别名；
- HSWQ：保留既有的 `builtins.__import__` 钩子，在 `comfy.memory_management` 完全导入之后（以 `read_tensor_file_slice_into` 存在为判据）的第一次导入时安装 fast-disk guard。

两个钩子都在 `main.py:266` 的 `import comfy.utils` 中触发——判定之后、`init_devices` 之前。

```python
_torch_preimport_warning_suppressed: bool = False
_TORCH_PREIMPORT_WARNING_MARKER = "Torch already imported"


def _torch_warning_suppression_disabled_by_env() -> bool:
    value = os.environ.get("QWENIMAGE_SUPPRESS_TORCH_WARNING", "").strip().lower()
    return value in ("0", "false", "no", "off", "disable", "disabled")


class _TorchPreimportWarningFilter(logging.Filter):
    """Drop ComfyUI's cosmetic 'Torch already imported' warning."""

    def __init__(self) -> None:
        super().__init__()
        self._suppressed = False

    def filter(self, record: logging.LogRecord) -> bool:
        if self._suppressed:
            return True
        try:
            message = record.getMessage()
        except Exception:
            return True
        if _TORCH_PREIMPORT_WARNING_MARKER in message:
            self._suppressed = True
            return False
        return True


def suppress_torch_preimport_warning() -> bool:
    global _torch_preimport_warning_suppressed
    if _torch_preimport_warning_suppressed:
        return True
    if _torch_warning_suppression_disabled_by_env():
        logger.info(
            "Torch pre-import warning suppression skipped "
            "(QWENIMAGE_SUPPRESS_TORCH_WARNING is disabled)"
        )
        return False
    try:
        logging.getLogger().addFilter(_TorchPreimportWarningFilter())
        _torch_preimport_warning_suppressed = True
        return True
    except Exception as exc:
        logger.debug("Failed to install torch pre-import warning filter: %s", exc)
        return False
```

```python
_ROTARY_TARGET_MODULE = "comfy.ldm.qwen_image.model"
_ROTARY_PARENT_MODULE = "comfy.ldm.qwen_image"
_rotary_hook_installed: bool = False


def _install_rotary_alias(qwen_image_model) -> bool:
    """Alias apply_rope1 onto an already imported comfy.ldm.qwen_image.model module."""
    global _qwen_apply_rotary_emb_compat_applied
    if qwen_image_model is None:
        return False
    if _rotary_shim_installed_on(qwen_image_model):
        _qwen_apply_rotary_emb_compat_applied = True
        return True
    if _comfyui_has_native_apply_rotary_emb(qwen_image_model):
        logger.info(
            "apply_rotary_emb compat skipped: ComfyUI already exports apply_rotary_emb"
        )
        return False

    nunchaku_needs = _nunchaku_qwenimage_still_imports_apply_rotary_emb()
    if nunchaku_needs is False:
        logger.info(
            "apply_rotary_emb compat skipped: ComfyUI-nunchaku no longer imports apply_rotary_emb"
        )
        return False

    from comfy.ldm.flux.math import apply_rope1

    qwen_image_model.apply_rotary_emb = _mark_rotary_shim(apply_rope1)
    _qwen_apply_rotary_emb_compat_applied = True
    logger.info(
        "Patched comfy.ldm.qwen_image.model.apply_rotary_emb -> apply_rope1 "
        "(ComfyUI-nunchaku Qwen Image compat)"
    )
    return True


class _RotaryAliasLoader:
    """Loader wrapper that applies the alias right after the target module executes."""

    def __init__(self, loader) -> None:
        self._loader = loader

    def __getattr__(self, item):
        return getattr(self._loader, item)

    def create_module(self, spec):
        return self._loader.create_module(spec)

    def exec_module(self, module):
        self._loader.exec_module(module)
        try:
            _install_rotary_alias(module)
        except Exception as exc:
            logger.error("Failed to apply apply_rotary_emb compat patch: %s", exc)


class _RotaryCompatFinder:
    """Resolve comfy.ldm.qwen_image.model through its parent package without importing it.

    Importing comfy here would pull torch during prestartup, which is exactly the state
    ComfyUI warns about. The finder only wraps the loader, so comfy and torch enter
    sys.modules at the moment the model module is actually imported, as usual.
    """

    def find_spec(self, fullname, path=None, target=None):
        if fullname != _ROTARY_TARGET_MODULE or fullname in sys.modules:
            return None
        parent = sys.modules.get(_ROTARY_PARENT_MODULE)
        parent_path = list(getattr(parent, "__path__", None) or [])
        if not parent_path:
            return None
        import importlib.machinery

        spec = importlib.machinery.PathFinder.find_spec(fullname, parent_path)
        if spec is None or spec.loader is None:
            return spec
        spec.loader = _RotaryAliasLoader(spec.loader)
        return spec


def apply_qwen_image_apply_rotary_emb_compat() -> bool:
    """Arm the apply_rotary_emb compat shim without importing comfy or torch.

    ComfyUI >= 0.24 removed comfy.ldm.qwen_image.model.apply_rotary_emb and
    ComfyUI-nunchaku still imports it. The alias is applied by an import hook: at once
    if the module is already imported, otherwise as soon as it is imported - which is
    still before ComfyUI-nunchaku reads the symbol.
    """
    global _qwen_apply_rotary_emb_compat_applied, _rotary_hook_installed
    if _qwen_apply_rotary_emb_compat_applied:
        return True
    if _rotary_compat_disabled_by_env():
        logger.info(
            "apply_rotary_emb compat skipped (QWENIMAGE_ROTARY_COMPAT is disabled)"
        )
        return False

    loaded = sys.modules.get(_ROTARY_TARGET_MODULE)
    if loaded is not None:
        try:
            return _install_rotary_alias(loaded)
        except Exception as e:
            logger.error("Failed to apply apply_rotary_emb compat patch: %s", e)
            return False

    if _rotary_hook_installed:
        return True
    try:
        sys.meta_path.insert(0, _RotaryCompatFinder())
        _rotary_hook_installed = True
        logger.info(
            "apply_rotary_emb compat armed: alias applies when comfy.ldm.qwen_image.model "
            "is imported (torch is not imported during prestartup)"
        )
        return True
    except Exception as e:
        logger.error("Failed to arm apply_rotary_emb compat hook: %s", e)
        return False
```

```python
def _load_patch_module(module_name: str, path: str):
    spec = importlib.util.spec_from_file_location(module_name, path)

        raise RuntimeError(f"Failed to load patch module spec from {path}")
    module = importlib.util.module_from_spec(spec)
```

### 4.6 `ComfyUI-HSWQ-Loader-and-Tools/prestartup_script.py` — 新增区块

```python
_FASTDISK_INSTALLED = False
_FASTDISK_INSTALLING = False


def _maybe_install_fastdisk() -> None:
    """Arm fast-disk support on the first comfy.memory_management import.

    Importing comfy here would pull torch during prestartup, and ComfyUI then logs
    "Torch already imported". comfy.memory_management is first imported by
    comfy.utils inside main.py, i.e. immediately after that check and long before
    init_devices, so the guard is still armed before aimdo initialises.
    """
    global _FASTDISK_INSTALLED, _FASTDISK_INSTALLING
    if _FASTDISK_INSTALLED or _FASTDISK_INSTALLING:
        return
    installer = globals().get("_install_fastdisk_support")
    if installer is None:
        return
    _FASTDISK_INSTALLING = True
    try:
        _FASTDISK_INSTALLED = bool(installer())
    except Exception as e:  # noqa: BLE001
        try:
            print(f"[HSWQ FastDisk] support install failed: {e}", flush=True)
        except Exception:
            pass
    finally:
        _FASTDISK_INSTALLING = False
```

```python
        spec.loader.exec_module(mod)
        return bool(mod.apply_comfy_aimdo_fastdisk_guard())
    except Exception as e:  # noqa: BLE001
        try:
            print(f"[HSWQ FastDisk] support install failed: {e}", flush=True)
        except Exception:
            pass
        return False
```

### 4.7 `ComfyUI-HSWQ-Loader-and-Tools/prestartup_script.py` — 删除的一行

```python
_install_fastdisk_support()   # removed: it ran during prestartup and imported comfy -> torch
```

其下的 `# Safety net: if comfy.ops somehow got imported before this hook could fire` 区块不变。

## 5. 这意味着什么

### 5.1 对本安装而言判定现在为假

在两个 prestartup 脚本按真实顺序执行之后（HSWQ 先、本包后）实测：

```
torch=False comfy=False transformers=True
```

`transformers` 由 docstring 补丁导入，在该环境栈上它不会导入 `torch`（每次补丁调用后实测 `torch=False`）。`torch` 不在 `sys.modules` 中，`main.py:262` 就不可能打印警告。

变更后的真实启动日志：`Torch already imported` 0 行、`Potential Error in code` 0 行、无 `[ERROR]`、无 traceback。

### 5.2 两个保护都仍在，且顺序正确

生效时机移到了 `main.py:262` 与 `main.py:296` 之间的窗口：

| 要求 | 实测 |
| --- | --- |
| 钩子在判定之后触发 | 生效发生在 `import comfy.utils`（`main.py:266`）之中 |
| guard 在 `init_devices` 之前安装 | `comfy_aimdo.control.init_devices` 只在 `main.py:296` 被调用 |
| 尚无 CUDA 上下文 | 生效点 `torch.cuda.is_initialized()` = `False` |
| 尚无 aimdo 工作线程 | 生效点 `threading.enumerate()` 无非主线程 |
| fast-disk 子补丁全部应用 | `control=True host_buffer=True model_vbar=True vram_buffer=True mem_slice=True` |
| init 之前已包装入口点 | `control.init_devices` / `init_device` / `get_devctx` 已包装；`host_buffer` 10 个标记；`model_vbar` 18；`vram_buffer` 4；`memory_management.read_tensor_file_slice_into._hswq_fastdisk_recoverable = True` |
| DiT-lock 与 INT8 ControlNet 仍生效 | 启动日志出现 `[HSWQ DiT-lock] ... armed`、`[HSWQ INT8 CN] Retrofit armed` |

启动日志顺序（原文）：

```
[HSWQ FastDisk] v0.38 fast-disk support armed (control=True host_buffer=True model_vbar=True vram_buffer=True mem_slice=True)
aimdo: aimdo_setup_hooks: installing 6 hooks
comfy-aimdo inited for GPU: ... (VRAM: 16283 MB)
DynamicVRAM support detected and enabled
```

guard 安装在 aimdo 自身钩子与设备初始化之前，这正是 guard 的 docstring 所要求的顺序。

### 5.3 rotary 别名的行为与之前完全一致

| 情况 | 行为 |
| --- | --- |
| ComfyUI 导出 `apply_rotary_emb`（0.46.0） | 钩子在模块加载时触发，第二道判定生效，不安装别名——日志实测：`apply_rotary_emb compat skipped: ComfyUI already exports apply_rotary_emb` |
| ComfyUI 移除该符号、nunchaku 仍导入 | 钩子在模块的 `exec_module` 中写入 `comfy.ldm.flux.math.apply_rope1`，即在 nunchaku 的 `from ... import apply_rotary_emb` 返回之前 |
| prestartup 运行时模块已被导入 | 立即路径：不经钩子，直接装上别名 |
| `QWENIMAGE_ROTARY_COMPAT` 关闭 | 跳过别名，与之前相同 |
| nunchaku 不再导入该符号 | 跳过别名，与之前相同 |

三道判定的内容与顺序都不变；只有*判定执行的时机*移动了。

### 5.4 不再隐藏任何东西

`logging` 过滤器已删除。如果任何节点——本包、HSWQ 或第三方——再次在 prestartup 期间导入 `torch`，警告会被打印出来并指明状态，而不是被隐藏。这正是判定存在的意义：它就是为了捕捉这种情况，唯一正确的应对是去掉提前导入。

`comfy.memory_management` 的判据还意味着 HSWQ 的工作会在第一次未成功时重试（`_FASTDISK_INSTALLED` 现在保存真实结果，而不是无论如何都写 `True`），因此一个只初始化了一半的 `comfy.memory_management` 不会静默地让 fast-disk 失去保护。
